# 操作规范

1. **标定期**（`skill calibrate`）：读取页面结构 / uiautomator 层级，产物是坐标、参考截图和元素的文字指纹（自愈用）。
2. **准备期**（每份 Issue 一次）：启动/打开一次 → 首页参考比对（失效即停）→ 模型选动态目标并冻结坐标 → setup。
3. **循环期**：只按坐标操作；相邻两次输入的开始时间 ≤ 950 ms（含设备侧耗时）；每步不截图、不发额外 adb 命令。
   - 异常门：Android 一条 logcat 流（崩溃 / ANR / 进程死亡 / 离开 App / App E 行=可疑）；Web 页面事件（pageerror / crash / 跳到登录或外域；console error 只记可疑）。
   - App 在后台被系统回收（`has died` 且前台不是本 App）不算崩溃。
4. **检查点**：每轮末尾一次截图（仅当计划有画面检查）→ 参考区域笔画比对 → 不一致才调视觉模型（`onlyOnAnomaly`）。不在聊天页 = 操作偏离：重进，不计命中。
5. **分层（W2-1）**：判定与定位都按 ① 确定性（logcat / pidof / `dumpsys input_method` / 无障碍文字 / Web 页面文字 / 区域比对）→ ② 排序插槽（本期为空）→ ③ 视觉模型 的顺序，只在检查点、准备期、预热轮、标定与自愈时使用，**循环每一步不读界面树、不读 DOM、不调视觉**。报告「判定分层统计」记录每次由哪一层决定、耗时多少；模型调用按用途计数。
6. **预热轮**：进循环前按计划跑一轮并逐步核验预期效果（Node 表的效果、元素自检类型、生命周期状态）；核验失败 → 「计划不可执行」，不进循环，失败回写草稿。
7. **前置条件构造**：只在 `platform/conversations.local.yaml` 的 `construct.allow` 会话里发消息 / 引用回复（成员都是池账号或用户本人）；`prepare-only` 的 Node（如 `teamily.quoteReply`）可以定位，但不能出现在循环里。
8. **视觉模型**：③ 层兜底；准备期定位无字面文字的目标；`ai` 类验收项；证据复核。每次调用都计数进报告。
9. **W2-2 可信结论**：预检不合格 → 「环境不合格」，不启动、不点击；每次运行写 `manifest.json`；运行标记 `r` + 6 位十六进制写进本次所有构造的文字，「最新消息」只认本次标记；App 每次冷启动，准备后清空旧草稿、收起键盘，结束时只做无副作用的复位（不删除、不撤回消息）。一轮的判定前提用 `require` 在轮内读一次（①，不是输入、不计动作间隔）；偏离轮不计有效尝试。
10. **禁止**：注入页面脚本、读源码、调试版、App 内部钩子；循环中发送会打扰他人的消息（通用模板只滚动、不发送）。
