## T7 多端协同（2026-11-03）

- 一个任务可以持有多个环境：`TaskRecord.envIds`，由调度器一次租齐（`leaseAll`），租不齐就一个都不租；结束时逐个释放、逐个检查；任务进程把自己记进每个租约。同一台手机上的 App 和浏览器可以归同一个同步任务，别的任务要等这台手机空出来。
- v1 任务类型 `sync`：`autotest task run --sync desktop-web,android-app [--rounds N]`（端名或环境 id，2–4 个）；超过 50 条消息需要完全授权；发送前核对会话在允许清单内（G3），不在就报错、不发送；每次发送和进入会话都记进副作用记录。结果：全部同步 → 已实现（13），存在未同步 → 未实现（14）。
- multi-account 类 Issue：如果要观察的是「同一条消息在各端都出现」，规划成多角色计划（`TestPlan.sync`：各端 + 轮数），走同一条执行路径，结论是已复现 / 未复现。2235 需要「转发」操作，SKILL 里没有转发 Node，仍然给出「无法生成计划」，原因写明这一点。
- 旧入口 `autotest sync` 已删除。
- 真机（`t-20261102185430-pk93`）：desktop-web（prod-aaron2）+ android-app（prod-aaron1），2 轮，经 `task run` 跑通，租约、账号分配、结果视图齐全，退出码 14。第 1 轮 App 端判为「未出现」：截图里消息已经到了，只是落在当前视图下方（右下角「↓ 1」）。改为：App 端没看到时先滑到最新消息再读一次。复测时手机已锁屏（有 PIN），提交被正确拒绝（51）；等解锁后复测。

合并后接着查 android-web，查到 3 个根因：
1. **手机浏览器的无障碍树不跟随页面内跳转**：uiautomator 与读树服务读到的都是同样的旧内容；页面加载后也只部分更新（会话列表只出现 2 行，而且重复）。规则从树里「找到」的锚点，可能属于已经不在屏幕上的页面，于是参考区域会在错误的页面上截取。改为：android-web 只在视觉确认屏幕上确实有锚点时才截取参考区域。
2. **底部导航栏在 Artifacts 页和会话列表上长得一样**，首页参考区域分不出两者；而这个页面要过好几秒才响应点击。于是「回到会话列表」看起来已经完成，其实还停在 Artifacts 页，会话是从 Artifacts 的卡片里选的。改为：每次点击后等页面真的变化并稳定下来，由视觉判断当前在会话列表还是会话里；准备阶段判断「是否在会话列表」也改由视觉回答（适配器新增 `atHomeList`）。
3. **视觉误定位**：把浏览器自己的后退键当成会话的返回箭头；在没有弹窗时去点「忽略」。改为：落在浏览器标题栏 / 底栏上的视觉点作废；先确认弹窗确实显示，再去点「忽略」。
