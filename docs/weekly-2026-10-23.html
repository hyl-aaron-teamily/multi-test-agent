第一周：从零搭起
能在生产环境下结论的测试台

multi-test-agent 是 Teamily 的客户端测试台。交给它一份 Issue，它判断问题类型、生成测试计划，确认一次后在 Android App、手机浏览器、手机视口 Web 和 Edge 桌面 Web 上以黑盒方式自动复现或验收，并留下可回放的证据。 本周完成 W1–W4 与 M5、M6 共 6 个里程碑，样例 Issue 的结论全部来自生产环境运行。

Purpose

它解决什么问题

客户端问题的复现和验收长期靠人工：偶发问题要人反复点，需求是否上线要人逐页看，多端是否同步要几个人对着屏幕。测试台把这些交给机器，人只在开始时确认一次。

Issue 进，
结论和证据出
自动分类 一次确认 动作间隔 ≤ 1 s 生产环境出结论 可重放的现场包

bug 类按上限跑满，给出「可复现 / 未复现」及执行步数；需求类逐条验收，列出已实现和缺项；服务端问题、不可执行的 Issue 直接说明原因，不做无用功。

偶发问题自动复现

按标定坐标高频重复用户操作，一次可跑上千步；人难以坚持的机械重复交给机器。

证据可核对、可重放

出事即导出现场包：出事前的录屏、对齐的日志、坐标级操作序列。命中先经录屏复核，开发拿到即可重放。

需求上线验收

在生产环境逐条核对需求是否落地，附截图列出已实现与缺项。

多端多账号同步

App、手机浏览器、桌面 Edge 各登一个账号进同一会话，验证一端发送、其余端都能看到。

黑盒，测的就是用户所见

不读源码、不装调试包、不向页面注入代码；只做用户能做的操作，只看用户能看到的现象。

一个入口

本地控制台统一发起 Issue 复现、自然语言任务、AI 探索、Monkey、IM 界面层收发和多端同步。

Positioning

补上「用户看到什么」这一层

im-loadtest 绕过客户端直连协议测服务端，它的 probe 测 Web SDK 算得对不对；屏幕上的表现此前没有工具测。三层合起来，覆盖从服务端到界面的完整链路。

Next

未来展望

第一周解决了「能跑通、结论可信」。下一阶段让它好用、常用、覆盖更全。

01
正式的控制台界面

当前控制台是最小可用版本。下一步做正式 UI：任务看板、报告与现场包在线查看、历史趋势。

02
多角色 Issue 计划

多端同步底座已就绪，下一步让测试计划直接编排多个账号和执行端，接上 1919、2235 这类多账号 Issue。

03
自动准备前置数据

由测试台自行构造用例需要的会话数据（如一条引用回复），减少对现有数据的依赖。

04
更多客户端形态

扩展到 iOS、WebView 与小程序 H5，覆盖 Teamily 全部客户端。

05
持续回归

接入 CI 与定时任务，定期跑 SKILL 自检、冒烟和已知 Issue 回归，App 或 Web 改版后第一时间发现。

06
规模化执行

多台手机、多机调度与任务恢复，支撑更长时间、更高频率的压测。

目标：每一份客户端 Issue，都自动带上一份可核对、可重放的结论。

开发不必再花时间复现，测试不必再守着屏幕重复点击；需求上线、多端一致性、偶发问题，都由测试台在生产环境给出证据。
