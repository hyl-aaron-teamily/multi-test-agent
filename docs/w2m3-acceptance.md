## §10.3 故障矩阵（每格之后紧跟一次正常任务，均得出结论「未复现」）

| 阶段 \ 故障 | 强杀任务进程 | 冻结进程（NtSuspendProcess） | 强杀平台后重启 | adb 断连（当时用 `adb kill-server`） |
|---|---|---|---|---|
| 预检 | PASS interrupted / 63 | PASS failed / 62 | PASS interrupted / 72 | 首次 FAIL（预检里 adb 报错被记成工具 60 → 已修）；重跑 PASS env-unfit / 50 |
| 准备 | PASS 63 | PASS 62 | PASS 72 | PASS 52（ENV_OFFLINE） |
| 预热 | PASS 63 | PASS 62 | PASS 72 | FAIL ×2：记录正确（52、环境不合格），但手机掉授权、无人授权超时 |
| 循环 | PASS 63（2 次） | PASS 62 | PASS 72 | PASS（任务进程因 EPIPE 崩溃 → 记 63；已修为 52） |
| 收尾 | PASS 63 | PASS 62 | PASS 72 | PASS（扛过断连，正常得出结论） |

停止位置都写在任务记录里（如 `循环 第 1 轮 第 1 步`）；恢复在独立进程 `env recover` 中进行，检查并清空被键入过的会话输入框。

### 门暴露并已修的缺陷

1. 预检里的 adb 异常逃出 `runPlan` → 记成工具失败：改为「环境不合格（online）」。
2. 常驻 adb shell 的 stdin EPIPE 是未处理的 `error` 事件 → 任务进程崩溃；shell 退出时等待中的命令被当作成功：改为以 `device offline` 拒绝（环境失败）。
3. `task run` 先查环境再查批准：手机离线时 31/32/33 被 52 掩盖；改为先校验批准（不消耗次数），再查环境，最后才扣次数。
4. 结果页术语提示嵌套替换破坏 HTML（一致性门发现）。
5. 平台被杀后再启动：被租着但还没启动的任务回队列；接管的任务结束后由看门狗补做释放与恢复。

### 观察

- 强杀平台（不带 `/T`）时任务进程也随之结束（tsx 包装进程），所以实测都是 72「服务重启中断」；「接管仍在运行的任务」路径只有单测覆盖。
- 这台手机在 `adb kill-server` 后多次掉 USB 调试授权、甚至从 adb 消失，需要人在手机上点「允许」；用户判断可能是数据线问题。
- 准备阶段强杀后有一次手机处于 PIN 锁屏（代码里没有发送电源 / 休眠键，原因不明）；环境正确进入「不合格：锁屏」，解锁后自动重检就绪。

## 2026-10-29 断连注入方式变更（用户决定）

- `adb kill-server` 会重启整个 adb 服务，这台手机每次都因此掉 USB 调试授权，必须有人点「允许」，故障矩阵因此反复卡住。
- 门脚本 `scripts/w2m3-gate.ts` 改为 `adb -s <手机> reconnect`（故障名 `adb-reconnect`，旧名 `adb-kill` 作别名）：只从主机侧踢开这台手机的连接，任务的常驻 adb shell 与 logcat 流照样断开，adb 服务和授权密钥不动，手机自行重连。
- 注入后手机 90 秒内没有回到 adb 就停止本次矩阵并写明原因，不再等人授权（原来最多等 10 分钟）。
- 以上表格与记录是旧方式下的结果，保留不改；新方式 2026-10-30 补跑预热一格，见下。

- 单测 209/209、typecheck 通过。

## 2026-10-30 真机验证中发现并修复

- Teamily 2.0.15 被强制升级拦住，暴露三处问题。
  - 冷启动闪屏上按返回会退出 App：现在先等首页或聊天页出现（≤ 20 秒）；App 不在前台时重新启动，不再按返回。
  - 桌面暗色壁纸通过了 SKILL 检查：墨迹比对现在会看参考图里浅色背景的像素，超过一半变暗就判为不匹配（`core/image.ts` 的 `SPILL_MAX`）。
  - 视觉选出的目标被当成会话名记进台账，导致环境被隔离：现在只有从屏幕上读到的标题才算会话名，标题未知的进入会话记为「目标 <id>（标题未知）」。
- 恢复侧也有两处改动。
  - 「清空输入框」不再被当作会话名。
  - 恢复时先检查当前打开会话的输入框（能读到时）。
- 2.0.20 有两处变化。
  - 改写按钮的无障碍名变成「用记忆强化 prompt」：标定正则已扩展。
  - 点改写会先弹确认框：标定记下框的取消按钮和区域；`tapRewrite` 看到确认框就记「有确认」并点取消，不算命中（W2-2 §5.2）。标定输入草稿改走 yadb：测试机输入法会吞掉 `input text`。只在键盘弹出时才按返回：键盘已收起时按返回会离开聊天页。SKILL 版本 2026.10.30-1。
- 2010（android-app，3 轮）：预热 + 3 轮都识别到确认框并点了取消，结论**未复现**（退出码 10）。之后环境恢复为就绪。
- **故障矩阵补跑**：warmup/adb-reconnect **PASS**。在预热的清空输入框一步执行 `adb -s <手机> reconnect`；任务以 `ENV_OFFLINE` 正常收尾，环境回到就绪，下一次正常任务得出未复现（`docs/w2m3-gate/faults-2026-10-30T08-12-54-826Z.json`）。矩阵合计 20/20。
