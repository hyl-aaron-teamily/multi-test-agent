Capabilities

现在能做什么

准备时用 AI，循环时用确定性操作：固定元素在标定时记下坐标，动态目标由模型在准备阶段选定后冻结；循环中只按坐标点、只靠事件流和每轮一次截图判断。

Issue → 分类 → 计划
→ 一次确认 → 黑盒执行 → 现场包
8 种预判类别 TestPlan schema 校验 替代端复选框 动作间隔 ≤ 1 s 偶现 1 次 / 必现连续 3 次

服务端问题、空文档直接出拒绝报告；需要第二账号或构造浏览器存储的出暂缓报告；需求类逐条验收，列出已实现和缺项。 bug 类在上限内未命中时如实写「未复现」，附执行步数与停止原因。

Teamily SKILL

四个执行端的页面地图与标定坐标：Android App、手机自带浏览器里的 Web、手机视口 Web、Edge 最大化窗口的桌面 Web。标定后自动逐个自检，只有失败项进人工复核；改版后参考区域对不上，执行器报「SKILL 失效」并停下。

pnpm autotest skill calibrate --surface …

事故现场包

Android 常开录屏环形缓冲 + 时间窗日志 + 崩溃缓冲 + dropbox；Web 用 trace 分块 + console + 网络记录。单文件查看器离线打开，点操作即跳视频。

incidents/<n>-<kind>/index.html

坐标级重放

按同一判定规则回答「能否复现」，并对比每轮落点，指出从第几轮起偏离原路径；可换节奏、冷启动重放。

pnpm autotest replay …/replay.json --variant all

证据复核

检查只比像素，会误报。命中后把录屏里出事前后两轮的画面条和被判定的截图交给视觉模型，对照 Issue 的「实际结果」：画面不符合就排除，不计命中。附预置用例回归复核本身。

pnpm autotest evidence cases

多端同步

端点池按「设备 × 执行端」分槽租用：同一台手机可同时开 App 与浏览器，本机开 Edge，各登录不同账号进同一会话；每轮一端发送，其余端必须看到。

pnpm autotest sync --roles desktop-web,android-web,android-app

退出 / 杀进程 / 重新加载

计划里可写「退出 App → 后台等待 → 杀后台进程 → 等待 → 冷启动 / 重新加载」，App 与手机浏览器都适用；计划内的退出不算闪退，杀进程会核实进程已不在。

pnpm autotest skill smoke --lifecycle cold

账号池

测试 / 生产账号分开租用，光标登录并缓存会话；手机上的登录状态写在端点池里（哪个账号登在 App、哪个登在浏览器），租用时只给登在那里的账号。凭据只在本地私有文件，不进日志和提交。

pnpm autotest accounts check --env prod

探索模式

自然语言任务、AI 探索遍历、固定 seed 的 Monkey 仍保留，用于没有 Issue 时的主动排查。

pnpm autotest mission "…"

IM 界面层收发

im-loadtest 的命令、指标与 SLO 搬到界面：真打字、真点发送，气泡在屏幕上出现才计时；另统计重复气泡与乱序。

pnpm autotest imui run --client …

How It Works

一份 Issue 的完整流程

从 Issue 文档到生产环境的结论与证据，五步。左右切换查看。

01

准备账号与标定

账号写在本地私有的 platform/accounts.local.yaml；每个执行端在每个环境标定一次，App 或 Web 改版后重做。

$ pnpm autotest accounts check --env prod
$ pnpm autotest skill calibrate --surface desktop-web --env prod
profile → desktop-web@prod.json　(14 elements, 0 self-check failures)
02

上传 Issue，生成计划

控制台选「Issue 黑盒复现」，上传或选择 Issue，点「生成计划」。能直接执行的出子用例；不能执行的写明原因。

预判　1594 · bug-intermittent · desktop-web
计划　选群 + 另一会话 → 切走再切回 → 键入 @ → 检查选择器弹出
拒绝　1614 server-side：无用户可见现象
03

一次性确认

Issue 端不可用（如 iOS）时，每个子用例一个复选框，只显示替代理由；只勾需要的，执行中不再打断。

[ ] s1 点赞可见　　替代 android-app | mobile-web
[x] s2 引用定位　　替代 android-app
[ ] s3 键盘一次弹出　替代 仅 android-app（浏览器模拟没有软键盘）
04

黑盒执行

启动一次 → 校验 SKILL → 模型选定动态目标并冻结坐标 → 循环。异常门只看 logcat / 页面事件；每轮末尾截一次图比对参考区域。

[run] 1594-desktop-web-v1: 未复现（上限内未出现）
05

看结论和现场包，必要时重放

报告给出结论、统计、准备阶段选了什么目标；命中时附现场包，可离线打开，也可按原坐标重放。

Boundaries

能力边界

测试台如实反映约束，不掩盖。用之前先知道这些。

◎
没有 iOS 执行端

iOS 问题只能经确认后在 Android 真机或手机 Web 上替代执行，报告首行标注替代，结论不直接代表 iOS。WebView、小程序也未接入。

!
视觉模型不适合下结论

挑目标可以，判定结果不稳定（同一画面会给出相反答案）。判定优先用参考区域比对和无障碍层核对，视觉只作补充，调用次数写进报告。

⇄
多端同步已有底座，Issue 计划尚未接上

多账号、多端同一会话的收发已能跑（sync）；1919、2235 这类 Issue 还没有生成多角色计划，仍是暂缓。同步耗时是「发送到检查看到」，含视觉核对与切换手机前台的时间，是上界。

☐
手机浏览器的几处约束

浏览器的无障碍树只在页面加载时建立，标定靠重新加载 + 视觉定位补齐；软键盘盖住表单按钮，登录用键盘回车提交；系统返回键会关掉标签页，只用页面里的返回。Teamily Web 重新加载后会恢复上次会话，而此时会话左上角返回无效（历史为空），需经 Artifacts → 聊天 → 返回回到列表——这是产品侧现象，已记录。

⚙
前置数据要事先存在

像「点引用跳到原消息」这类用例依赖会话里已有的数据；测试台还不能稳定地自行构造前置条件，构造不出时报「执行失败」而不是误判。

◔
「未复现」不等于没问题

偶发问题在上限内没出现，只说明这次没碰到；报告写明执行了多少步、因何停止。App 或 Web 改版后需重新标定。

≡
CI 未在真实 runner 上跑过

工作流只做了语法检查。Monkey 仍不要对生产账号运行。
