## 读树服务的真机发现（2026-10-30 — 31）

1. **小米安装确认**：`adb install` 被拒 `INSTALL_FAILED_USER_RESTRICTED`——「USB 安装」已开（`persist.security.adbinstall=1`），首次安装时手机弹确认框，要人点「继续安装」（无人点 → 被取消）；之后 v2–v6 覆盖安装（`install -r`）没有弹框，用户未在手机上操作（用户确认，版本迭代默认允许）。同时修了两处：未生效的可选配置项此前报「通过」，`env check` 不会进修复流程（改为已同意未生效 = `pending`，跑一次修复）；修复流程里的安装错误此前只在被丢弃的修复轮里（改为写进恢复动作与审计）。刚装完立即启用会被系统丢掉，改为等待后启用并复核（最多 3 次）。doctor 在服务未安装时给出这一步「需人工」。
2. **v1 返回过期的树**：聊天页已打开（uiautomator 读到输入框），服务仍返回会话列表。原因：无障碍服务的节点缓存靠它收到的事件失效，v1 只订阅了窗口切换事件。v2 订阅全部事件（处理函数仍为空）。基准脚本的一致性检查发现了它——此前「会话列表 95.6%」看起来正常。
3. **v2 少列被遮挡的节点**：聊天页一致率 86.7%，差异全是 uiautomator 列出、服务标为用户不可见的节点（滚到标题栏下的消息，边界甚至倒置）。按用户决定（与 uiautomator 一致，降低既有判定的风险）v3 导出全部节点；主机侧只剪掉「从屏幕边界之外开始」的不可见节点（列表底部屏幕外的行，uiautomator 也不列）。结果两屏 100%。
4. **一次错误的归因（v4、v5，已撤回）**：v3 上 2010 的平均动作间隔从 0.88 s 升到 1.45 s，`tapRewrite` 内的间隔约翻倍。先归因为「订阅全部事件让 App 多派发事件、变慢」，改出 v4（关缓存：每次读 1.3–1.5 s）和 v5（每次读前清缓存：0.6–0.7 s），但 v5 上间隔仍是 1.44 s。随后对照测量：服务开 / 关 / 再开时截图 p50 1572 / 1584 / 1564 ms——变慢的是手机截图本身（当天早些时候约 0.5 s），与服务无关；`tapRewrite` 的等待由截图轮询组成（稳定帧 + 每 400 ms 一帧），截图多 1 s，间隔就多 1–2 s。最终 v6 = v3 的做法（订阅全部事件、保留缓存）。教训：比较运行耗时要同一时段开关对照，不能跨时段比较。
- 主机侧剪枝（`core/a11y-service.ts#pruneOffscreen`）：服务标为不可见的节点里，从屏幕边界外开始的连同子树去掉（列表底部屏幕外的行）；没有正面积的只去掉自身（滚出顶部的行边界倒置，中心落在另一条可见的行上，按文字定位会点错）。不可见但有实际区域的（标题栏下的消息）保留，与 uiautomator 一致。
- 主机要求的服务版本 `A11Y_VERSION = 6`，旧版本视为需重装（`outdated`）。

## 读树后端（§4.1）

- `core/tree-backend.ts`：所有 Android 读树经 `readTree`；A = uiautomator（原实现，按设备串行），B = 常驻服务；B 失败时本次退回 A，原因计数（报告「读树后端」一节）。
- 设备声明：`platform/devices.yaml` 的设备项加 `treeBackend: a11y-service`（或环境变量 `AUTOTEST_TREE_BACKEND`）。声明后环境多一个**可选**配置项 `a11y-service`：`env check` / 恢复时安装并追加启用（保留手机上其他无障碍服务），预检只检查不安装；装不上 / 不响应 → 基线项通过但写明「退回 uiautomator」，环境不判不合格。
- 协议：手机回环 `127.0.0.1:18765`，`/ping`（无令牌）、`/dump?token=`（uiautomator 同格式 XML）；令牌经 `am broadcast` 下发，接收器要求 `WRITE_SECURE_SETTINGS`（只有 adb shell / 系统有）；主机经 `adb forward tcp:0` 访问，端口按设备复用、进程退出时移除，残留由 `doctor --fix` 清理。
- 卸载：`adb uninstall ai.autotest.a11y`（`core/a11y-service.ts#uninstallA11y` 先从启用列表移除）。

## 执行前校验（§4.3）

- `executor/pretap.ts`：记住循环外决定的每个点（①/② 定位、冻结目标、自愈元素）的指纹；`enter` / `prepare` / `re-entry`（偏离后重进）阶段与 Android 标定自检打开，循环关闭。
- 树校验权重：资源 id 0.5、文字 0.4、边界 0.3、位置 0.3；≤ 8 px 通过，≤ 120 px 就地修正，更远 = 偏移；命中测试点到无层级关系的节点 = 遮挡；找不到 = 消失。拦截记「执行事件」并存两帧截图（`<runDir>/pretap/`）。
- 没有指纹（视觉定位的目标）或 android-web（浏览器无障碍树页面内跳转不更新）：决策时截图对比当前截图，点击点周围 < 5% 像素变化即通过，否则视觉模型判断两帧（只回答是否 / 状态 / 把握度），视觉不可用 = 不确定（照点，记录）。
- 准备期被拦截的会话行：重新挑行一次再执行 setup。
