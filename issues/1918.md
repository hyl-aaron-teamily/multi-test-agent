## Summary
On the iOS mobile app, in a 1:1 Teamily Agent chat ("Aiden's Personal AI"), a math formula in an agent reply inside a message bubble is not converted/rendered — the raw LaTeX source is displayed verbatim, including backslash commands, braces and the $$ delimiters (e.g. CPM = \frac{广告花费}{展示次数} \times 1000 and the block CPM = \frac{500}{100000} \times 1000 = $5). The same message renders correctly on web and macOS, where the display formula is typeset with a proper fraction bar. Reported by Aiden (Teamily CEO) with side-by-side screenshots. Filed separately from #1416 (channel-side Slack/iMessage formula loss) because the root cause here is on the client-side mobile rendering path, not the outbound channel.

## Steps to reproduce
1. Open the Teamily iOS app and enter a 1:1 chat with an agent (reproduced in "Aiden's Personal AI").
2. Ask the agent a question whose answer contains a math formula — e.g. send "CPM 是什么" (inferred).
3. Wait for the agent reply, which contains LaTeX formulas — an inline-style formula and a $$-delimited block formula.
4. Observe the message bubble: the formula is shown as raw LaTeX source code.
5. Open the same conversation on web / macOS and compare — there the formula renders as typeset math.

## Expected result
Formulas in an agent reply should be rendered as typeset math (LaTeX -> layout) inside the message bubble on every client, consistent with web and macOS.

## Actual result
On the iOS app the formula is not converted: the raw LaTeX source is shown as plain text inside the message bubble — literal \frac{...}{...}, \times, braces and the $$ delimiters are all visible instead of a laid-out formula.

- **Frequency**: Always

## 摘要
在 iOS 手机 app 的 1:1 Teamily Agent 会话（「Aiden's Personal AI」）中，agent 回复的消息气泡里的数学公式没有做格式转换（LaTeX → 排版），而是直接显示了原始 LaTeX 源码——包含反斜杠命令、花括号和 $$ 分隔符，例如 CPM = \frac{广告花费}{展示次数} \times 1000，以及块级公式 CPM = \frac{500}{100000} \times 1000 = $5。同一条消息在 web 端和 macOS 端显示正常，块级公式已排版出分数线。由 Aiden（Teamily CEO）反馈并提供了对照截图。该问题与 #1416（渠道侧 Slack/iMessage 公式标记丢失）分开记录，因为本次根因在客户端移动端渲染链路，而非外发渠道。

## 复现步骤
1. 打开 Teamily iOS app，进入与 agent 的 1:1 会话（复现于「Aiden's Personal AI」）。
2. 向 agent 提问一个答案中包含数学公式的问题——例如发送「CPM 是什么」（推断步骤）。
3. 等待 agent 回复，回复中包含 LaTeX 公式——一个行内（inline）公式和一个 $$ 包裹的块级公式。
4. 观察消息气泡：公式以原始 LaTeX 源码形式展示。
5. 在 web / macOS 端打开同一会话对照，公式已排版为正常数学格式。

## 预期结果
消息气泡中的公式应在所有客户端都渲染为排版后的数学格式（LaTeX → 排版），与 web / macOS 保持一致。

## 实际结果
iOS app 上未做转换：消息气泡内直接显示了原始 LaTeX 源码——字面的 \frac{...}{...}、\times、花括号以及 $$ 分隔符全部可见，而不是排版后的公式。

## 补充信息
- **功能区域**: 消息渲染 / 聊天气泡（客户端—移动端）
- （推断）该会话为 1:1 Teamily Agent 会话，标题显示为「Aiden's Personal AI」。
- 受影响容器为消息气泡（agent 回复）；反馈未涉及文档或卡片场景，请确认是否仅限聊天气泡。
- 输入框中选择的是「Instant」模式（截图中可见），一并记录，但应无影响。
- 相关但不重复：#1416（渠道侧 Slack/iMessage 公式标记丢失，属外发渠道渲染）；#1903（iOS 已发送气泡中 @ 未渲染）；#771（RN IM 文本格式丢失）；#978（发送方气泡富文本被剥离）；#1020（Android RN markdown 表格被裁剪）；#1823（转发丢失富文本格式）。
- 需要定位：(1) iOS app 是否缺少 LaTeX → 排版的渲染链路，还是渲染库/字体在移动端未生效；(2) 仅 iOS 还是 Android 同样存在；(3) 确认场景是消息气泡、文档还是卡片。
- 补充：macOS 截图中第二个 $$...$$ 块级公式仍显示为原始源码，说明块级公式的分隔符处理与行内公式不同——属于同一渲染链路的一个子场景，建议一并覆盖。
