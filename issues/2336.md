## Summary
yara (QA) reports that Teamily exposes at least three separate 🔔 notification entries, each with its own independent unread state, so a user has to check several places to see all notifications and easily misses them. Evidence: three screenshots showing the bell in (1) the profile page header (top-right, with a green unread badge '9'), (2) the Artifacts module page header (top-right of the main content area, no badge), and (3) the CloudDoc / deliverable document header (top-right, between Help and the avatar, no badge). Request: consolidate these entries so that a single place shows all notifications with one consistent unread state. This is the structural fix for the root cause behind the related open bug #2334 (the Artifacts in-page bell shows unread while the left-sidebar Artifacts entry shows no badge).

## Steps to reproduce
1. Sign in to Teamily Web (teamily.ai).
2. Open the profile page (e.g. /profile) — a 🔔 bell sits in the header top-right, between the community icon and the share icon, and carries an unread badge. [screenshot 1]
3. Open the Artifacts page — a separate 🔔 bell sits at the top-right of the main content area, to the right of the grid/list-view toggle and to the left of the '筛选' (Filter) button, with its own (empty) unread state. [screenshot 2]
4. Open a CloudDoc / deliverable document — a third 🔔 bell sits in the top-right header, between the Help icon and the avatar. [screenshot 3]
5. Compare the three entries: each is an independent entry point with its own unread state, and no single place lists all notifications.

## Expected result
One consolidated notification entry: a single notification center, reachable from one consistent location, that aggregates notifications from every module under a SINGLE shared unread state (badge / count) kept in sync everywhere. Reading or clearing a notification updates the unified state. If module-level entries are kept, they must read from the same unread state instead of maintaining independent ones — so the badge can never disagree between surfaces. Concrete proposal to confirm with product: an aggregated 'Notifications' entry in the global navigation (e.g. the left icon rail) that shows all notifications with per-source grouping, and a single unread count shared by the rail entry, the page-level bell, and any module badge.

## Actual result
At least three separate 🔔 entries exist, each with an independent unread state: (1) the profile page header, (2) the Artifacts page header, and (3) the CloudDoc / deliverable document header. A user must visit each module separately to check notifications, and the unread badges disagree between surfaces — e.g. on the Artifacts page the in-page bell reports unread while the left-sidebar Artifacts entry reports none (#2334).

## 摘要
yara（QA）反馈：Teamily 目前至少有三处各自独立的 🔔 通知入口，每处维护自己的未读状态，用户必须分别到多个位置查看通知，且很容易漏看。证据：三张截图分别显示（1）个人主页头部右上角铃铛（带绿色未读角标「9」）、（2）Artifacts 模块页主内容区右上角铃铛（无角标）、（3）CloudDoc / 交付物文档头部右上角铃铛（位于帮助图标与头像之间，无角标）。诉求：把这些分散的通知入口整合起来，在一个统一入口展示全部通知，并共用唯一的未读状态。本单也是相关开放 bug #2334（Artifacts 页内铃铛有未读、左侧边栏 Artifacts 入口无角标）的根因层面的结构性修复。

## 复现步骤
1. 登录 Teamily Web（teamily.ai）。
2. 打开个人主页（如 /profile）——头部右上角、社群图标与分享图标之间有一个 🔔 铃铛，带未读角标。【截图 1】
3. 打开 Artifacts 页面——主内容区右上角、网格/列表切换图标右侧、「筛选」按钮左侧有另一个独立的 🔔 铃铛，有其自己的（空）未读状态。【截图 2】
4. 打开一个 CloudDoc / 交付物文档——头部右上角、帮助图标与头像之间有第三处 🔔 铃铛。【截图 3】
5. 对比三处：它们是三个彼此独立的入口组件，各自维护未读状态，且没有任何一个位置可以集中看到全部通知。

## 预期结果
统一为一个通知入口：只在固定的一处提供通知中心，聚合各模块的通知，并共用同一个未读状态（角标/计数）且在各处保持同步；已读或清除通知后统一状态同步更新。若仍需保留模块级入口，则必须读取同一份未读状态，而不是各自维护，从而保证任意两处角标不会互相矛盾。具体方案待与产品确认，建议方向：在全局导航（如左侧图标栏）提供聚合的「通知」入口，展示全部通知并按来源分组，未读计数由导航入口、页面级铃铛与各模块角标共用。

## 实际结果
至少存在三个独立的 🔔 入口，各自维护未读状态：（1）个人主页头部、（2）Artifacts 页面头部、（3）CloudDoc / 交付物文档头部。用户必须分别进入各模块查看通知，且各处未读角标不一致——例如在 Artifacts 页，页内铃铛提示有未读，而左侧边栏 Artifacts 入口没有任何角标（#2334）。
