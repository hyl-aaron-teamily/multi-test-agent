## Summary
When a message whose content contains a Markdown link is quoted in a reply, the quote block preview on iOS renders the raw Markdown source instead of a parsed link. The link is shown as '[https://github.com/TensorOpera-Inc/chat-web/pull/654](https://github.com/TensorOpera-Inc/chat-web/pull/654)', so the same URL appears twice. Reported by Aiden (seen in the group 'Payment & Team Subscriptions', Henry quoting a message from Tmly Quan). This is a regression-family sibling of #1896 but in a different render path (quote preview, not the message popup).

## Steps to reproduce
1. Send a message whose content contains a link that is stored as Markdown link syntax, e.g. a GitHub PR URL (in the evidence: a message from Tmly Quan containing https://github.com/TensorOpera-Inc/chat-web/pull/654).
2. Long-press that message and choose Quote/Reply, then send a reply (in the evidence: Henry replying with an image + text).
3. Open the conversation on the iOS app and look at the quote block shown above the reply bubble.

## Expected result
The quote block preview shows the quoted message as plain display text: the link appears only once (either the URL or its label, optionally as a link), with no Markdown syntax such as '[', '](' or ')'. The preview should match how the original message bubble renders the link.

## Actual result
The quote block preview prints the Markdown link source verbatim: '[https://github.com/TensorOpera-Inc/chat-web/pull/654](https://github.com/TensorOpera-Inc/chat-web/pull/654) 测...'. The URL is displayed twice (once as the label in brackets, once as the target in parentheses), taking two lines of the preview and truncating the actual quoted text.

## Severity
- **Level**: Medium
- **Frequency**: Always

## Environment
- **Platform / OS / Browser**: iOS app (confirmed from screenshot); Web / macOS / Android not verified - please check whether the quote preview component is shared

## Additional context
- **Feature area**: Messaging / UI - Quote (reply) block preview, Markdown link rendering
- Reported by Aiden. cc @Diff-Jack (Jack) @cola-coding (Cora).
- Location: the duplication is INSIDE the quote block (quoted preview), not in the reply body. The reply body text renders normally.
- Type of duplication: raw Markdown link syntax '[text](url)' left unparsed (label == url, so the URL shows twice). It is NOT a plain-text URL being copied, and no 'mailto:' link is involved.
- Related: #1896 (message popup renders a URL as duplicated '[link]link'). Same symptom family - Markdown link markup leaking into a read-only display surface - but a different render path: the quote preview appears to build its summary from the raw message content without a Markdown parse/strip step. Suggest fixing both with a shared 'markdown to plain preview text' helper used by quote preview, popup, conversation-list snippet and notifications.

## 摘要
在回复中引用一条包含 Markdown 链接的消息时，iOS 端引用块预览直接显示了 Markdown 源码而不是解析后的链接，显示为「[https://github.com/TensorOpera-Inc/chat-web/pull/654](https://github.com/TensorOpera-Inc/chat-web/pull/654)」，同一个 URL 出现两次。反馈人：Aiden（场景：群「Payment & Team Subscriptions」中 Henry 引用 Tmly Quan 的消息）。与 #1896 属于同类问题，但出现在不同的渲染路径（引用预览，而非消息弹窗）。

## 复现步骤
1. 发送一条内容中包含以 Markdown 链接语法存储的链接的消息，例如 GitHub PR 链接（截图中为 Tmly Quan 发送的包含 https://github.com/TensorOpera-Inc/chat-web/pull/654 的消息）。
2. 长按该消息，选择引用/回复，并发送回复（截图中为 Henry 回复图片 + 文字）。
3. 在 iOS App 中打开该会话，查看回复气泡上方的引用块。

## 预期结果
引用块预览应以纯展示文本显示被引用消息：链接只出现一次（显示 URL 或其 label，可带链接），不应出现 '['、']('、')' 等 Markdown 语法，且应与原消息气泡中的链接展示一致。

## 实际结果
引用块预览原样输出 Markdown 链接源码：「[https://github.com/TensorOpera-Inc/chat-web/pull/654](https://github.com/TensorOpera-Inc/chat-web/pull/654) 测...」。URL 被显示两次（方括号 label 一次、圆括号 target 一次），占满两行预览并截断了真正的引用正文。

## 补充信息
- **功能区域**: 消息 / UI —— 引用（回复）块预览，Markdown 链接渲染
- 反馈人：Aiden。cc @Diff-Jack（Jack）@cola-coding（Cora）。
- 位置：重复 URL 出现在引用块内（被引用内容预览），不在回复正文；回复正文渲染正常。
- 重复类型：Markdown 链接语法 '[text](url)' 未被解析（label 与 url 相同，所以 URL 显示两次），不是纯文本 URL 被复制，也不涉及 'mailto:' 链接。
- 关联：#1896（消息弹窗把 URL 渲染成重复的 '[link]link'）。症状同类——Markdown 链接标记泄漏到只读展示层——但渲染路径不同：引用预览似乎直接用原始消息内容生成摘要，缺少 Markdown 解析/剥离步骤。建议抽一个统一的「Markdown → 纯文本预览」工具，供引用预览、消息弹窗、会话列表摘要和推送通知共用，一并修复。
