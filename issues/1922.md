## Summary
Aiden reports that the long-standing bug in which the second line of a text message bubble is not displayed has reappeared. On the reporter's own sent message, only the first line of content is shown and the remaining content is clipped with no ellipsis, so the message reads as though it were truncated mid-sentence. Reproduction path reported this time: send a message, leave the app to do something else, and later — after another participant replies — reopen the app and return to that conversation; the second line of the reporter's own message is then missing. The same symptom was reported on 2026-06-23 ("after opening the app for the first time on a given day the second line of the message content is not displayed; restarting the app restores it") and again on 2026-09-11, when the reporter asked for it to be fixed with the highest priority — so this is at least the third occurrence, and one that a prior fix did not permanently resolve. Because it only affects messages longer than one line and silently hides part of the user's own text, it is a trust-damaging core-messaging defect rather than a cosmetic one.

## Steps to reproduce
1. Send a text message that is longer than one line in any conversation.
2. Leave the app / switch away to do something else (background the client, or use another app).
3. Wait until another participant replies in that conversation.
4. Reopen the app and return to the same conversation.
5. Observe the reporter's own message bubble — only the first line of content is visible; the second line is missing (no ellipsis, no partial glyphs, no 'show more' affordance).
6. (Historical variant, 2026-06-23 report, inferred) Cold-start the app for the first time on a given day, open the conversation, and observe the same clipping; relaunching the app restores the missing line.
7. (Historical variant, 2026-09-11 report, inferred) The same clipping occurs on newly sent messages while reading the conversation, and was hit at least three times by the reporter on that day.
8. (inferred) Confirm on each candidate client — iOS app, Android app, web, macOS — which builds reproduce the clipping.

## Expected result
Every message bubble renders its full text height on first layout and on every re-layout after re-entering the conversation. A message longer than one line shows all of its lines (or, if truncation is intended, a 'show more' affordance), regardless of whether the content came from the local cache or from a later sync.

## Actual result
The second line of the reporter's own message bubble is not rendered: the bubble keeps a height that fits only the first line, and the remaining text is clipped without any ellipsis or expand affordance. In the first-open / long-message observation the message text is cut mid-sentence inside the bubble. Restarting the app temporarily makes the missing line reappear, which indicates the content is present in the data but the bubble height is not recomputed.

## 摘要
Aiden 反馈，文字消息气泡第二行不显示的问题又出现了。复现路径：自己发了一条消息 → 切出去干别的 → 等会儿别人回复后再打开 app → 自己这边显示掉了一行字（消息内容第二行不可见）；气泡高度看起来只够第一行，剩余文字被裁掉且没有省略号。该问题此前已反馈过两次：2026-06-23 首次反馈（当天首次打开 app 后消息第二行不显示，重启 app 后恢复），2026-09-11 再次反馈并要求最高优先级修复。因此这至少是第三次出现，且此前的修复没有根治。由于只影响长于一行、且被裁掉的是用户自己发出的文字，属于核心消息体验问题，而非纯视觉问题。

## 复现步骤
1. 在任意会话中发送一条超过一行的文字消息。
2. 切出去做别的事情（把客户端切到后台，或使用其他 app）。
3. 等待该会话中其他人回复。
4. 重新打开 app 并回到该会话。
5. 观察自己发出的消息气泡——只有第一行内容可见，第二行消失（无省略号、无残留字形、无「展开更多」入口）。
6. （历史变体，2026-06-23 反馈，推断）当天首次冷启动 app 后进入会话，可观察到同样的裁切；重启 app 后缺失的行恢复。
7. （历史变体，2026-09-11 反馈，推断）在查看会话时新发出的消息也会出现同样裁切，当日至少重复遇到三次。
8. （推断）确认 iOS、Android、Web、macOS 各端分别是否复现。

## 预期结果
消息气泡在首次布局以及重新进入会话后的每次重排时，都应完整渲染全部文字高度。超过一行的消息应显示所有行（若产品设计需要截断，则应提供「展开更多」入口），无论内容来自本地缓存还是后续同步补全的数据。

## 实际结果
自己发出的消息气泡第二行未被渲染：气泡高度只容纳第一行，剩余内容被裁掉，且没有省略号或展开入口。首次打开/长消息场景下表现为气泡内文字在句中截断。重启 app 后缺失的行会暂时恢复，说明数据中内容是在的，只是气泡高度没有被重新计算。
