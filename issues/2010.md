## Summary
On the Teamily iOS app the AI Rewrite control sits inside the chat composer, in the icon row directly under the text input field - exactly where the thumb naturally lands while typing. Tapping it by accident, which the reporter says happens very easily, rewrites/overwrites the text the user has already typed, so the draft is destroyed and has to be retyped. The reporter notes that Rewrite is not a high-frequency feature on mobile and suggests confirming with Aiden whether the button can simply be hidden on mobile, and asked for this to be tracked as high priority.

## Steps to reproduce
1. Open the Teamily iOS app and enter any chat conversation.
2. Tap the message input field and start typing a message (the keyboard opens).
3. While typing, accidentally tap the AI Rewrite icon in the composer toolbar - the grey sparkle / 'magic' glyph in the icon row below the input field, circled in red in the attached screenshot.
4. Observe that the text already typed is rewritten / overwritten and the original draft is gone.

## Expected result
Typed input must not be silently destroyed by an accidental tap. Tapping the AI Rewrite control should either require an explicit confirmation before applying, or preserve the original draft so the user can undo / restore it. Per the reporter's suggestion, the mobile app should consider hiding this non-high-frequency control altogether, or moving it out of the direct typing/thumb area.

## Actual result
A single accidental tap on the AI Rewrite control replaces the text the user had already typed - the draft is lost and must be retyped. There is no confirmation step and no undo. Because the control sits in the composer area where the finger is already operating while typing, the reporter states it is 'especially easy' to hit by mistake. The screenshot shows the composer with the Rewrite control circled in red and an empty input field showing only the 'Type a message...' placeholder, while the iOS Pinyin candidate bar is still active - consistent with an in-progress typing session whose text has just been wiped from the field.

## 摘要
iOS 版 Teamily 的聊天输入区（composer）中，「改写 / AI 改写」控件位于输入框正下方的图标行里，也就是用户打字时拇指自然落点附近，非常容易被误触。一旦误点，已经输入的原文会被改写 / 覆盖，用户草稿丢失、只能重新输入。反馈人指出该功能在移动端并非高频功能，建议与 Aiden 确认移动端是否可以直接隐藏该按钮，并要求按高优记录。

## 复现步骤
1. 打开 iOS 版 Teamily App，进入任意聊天会话。
2. 点击消息输入框并开始打字（键盘弹出）。
3. 打字过程中，不小心点到输入框下方工具条里的「改写 / AI 改写」图标（灰色星芒 / magic 图标，即截图红圈标出的位置）。
4. 观察到已经输入的文字被改写 / 覆盖，原文丢失。

## 预期结果
已输入的内容不应因为一次误触而被静默销毁。点击「改写」控件应至少要求一次明确确认，或保留原文以便用户撤销 / 恢复。按反馈人的建议，移动端可考虑直接隐藏这个非高频控件，或把它移出打字时手指直接操作的区域。

## 实际结果
单次误触「改写」控件就会替换用户已经输入的文本，草稿丢失、必须重新输入；既没有确认步骤，也没有撤销。由于该控件位于打字时手指已经在操作的输入区，反馈人表示「特别容易误触」。截图中该「改写」控件被红圈标出，而输入框内只剩「Type a message...」占位文案、键盘的拼音候选栏仍在活跃状态 —— 与「正在打字、文字刚被清空」的情形一致。
