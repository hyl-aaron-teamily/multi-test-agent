## 摘要
Henry 从与 Shok 的单聊（私聊）会话中转发了一条消息。发送方（Henry，macOS）能看到该转发消息，接收方（Shawn）在 iOS 端也能看到 —— 但同一条消息在 Web 与 Desktop（构建 101）上完全不出现。同一账号在不同端看到的会话内容不一致，用户无法判断是消息丢失了，还是产品有意在部分端隐藏转发消息。反馈人明确要求产品/研发确认预期的可见性规则（发送方 vs 接收方、转发消息的可见性），并且无论规则如何设计，都应保证多端体验一致。影响：在 Web/Desktop 上阅读会话的用户会认为该消息从未发出，而 iOS 用户却能看到 —— 群会话中信息不对称，会损害用户对消息投递的信任。

## 复现步骤
1. 1. 在与 Shok 的单聊（私聊）会话中，将一条消息转发出去（具体使用的转发入口未指定 —— 请确认）。
2. 2. 在发送方（Henry，macOS 客户端）打开目标会话，确认转发消息存在 —— 存在（截图 2）。
3. 3. 在接收方（Shawn）的 iOS 端打开同一个目标会话 —— 转发消息存在，带有「Forwarded from Shok」来源标记（截图 1）。
4. 4. 同一账号在 Web 与 Desktop（构建 101）上打开同一会话。
5. 5. 对比三端：iOS 能看到该转发消息，Web 与 Desktop（101）看不到。

## 预期结果
同一条转发消息应在同一账号的所有端（iOS / Web / Desktop）都可见；若产品确实有意按端或按角色（发送方 vs 接收方）限制转发消息的可见性，则该规则必须明确且有文档，且各端仍应保持一致。无论哪种情况，多端体验都应一致，不应出现「一端有、另一端静默缺失」。

## 实际结果
转发消息在 iOS 端可见（带「Forwarded from Shok」标记），在发送方的 macOS 端也可见，但在同一账号的 Web 与 Desktop（构建 101）上完全不出现。反馈人原话：「我这 web 和 desktop（101）都没看到，只有 ios 看到这个消息」、「web 和 desktop 没看到，只有 ios 有，有不一致问题」。Web/Desktop 上无报错、无占位符、无任何提示 —— 消息就是不在，用户无法判断是丢失还是被有意隐藏。
