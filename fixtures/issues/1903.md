## Summary
In the Teamily iOS app (TestFlight build 386), after @-mentioning a member in a group chat and sending the message, the mention is NOT rendered in the message bubble — the bubble shows the text without the @ mention (no mention styling, no mentioned name). The conversation-list preview for the very same message DOES render the mention correctly, which proves the mention data is intact in the message payload and only the in-chat bubble rendering layer drops it. This breaks a core IM capability: recipients of the bubble cannot tell who was mentioned, and the sender cannot visually confirm that the mention was actually sent.

## Steps to reproduce
1. Launch the Teamily iOS app on TestFlight build 386 (mobile client).
2. Open a group chat.
3. Compose a message and @-mention a group member (e.g. a message ending with @Henry).
4. Send the message.
5. Observe the sent message bubble: the @-mention is not rendered — the bubble shows plain text with no @ mention and no mention styling.
6. Return to the conversation list and observe the preview of the same message: the @-mention IS rendered correctly (e.g. "2点在压测吗? @Henry").

## Expected result
The sent message bubble should render the @-mention with mention styling and the mentioned member display name, consistent with the conversation-list preview and with the Web/Desktop client behaviour.

## Actual result
The message bubble renders the message text without the @-mention (mention not displayed, no mention styling). The conversation-list preview of the same message renders the mention correctly ("2点在压测吗? @Henry"), demonstrating that the mention exists in the message data and that only the in-conversation bubble rendering fails.

## Severity
- **Level**: High
- **Frequency**: Always

## Environment
- **Platform / OS / Browser**: iOS / Teamily mobile app / TestFlight build 386

## Additional context
- **Feature area**: Messaging / UI Rendering (mention rendering)
- Reporter: Jane (Teamily PM/QA). Reported 2026-09-21.

## 摘要
在 Teamily iOS 客户端（TestFlight 386 版本）中，群聊里 @ 某成员并发送消息后，消息气泡内没有渲染出 @ 的样式与内容（@ 未显示，退化为纯文本）；而同一会话列表的预览却正确显示了 @。这说明消息数据中的 @ 是完整的，问题只出在会话内消息气泡的渲染层。@ 是 IM 的核心能力，此缺陷会导致接收方无法看出被 @ 的人是谁、发送方也无法确认 @ 是否真的发出。

## 复现步骤
1. 在 TestFlight 386 版本的 Teamily iOS 客户端上启动 App。
2. 进入一个群聊。
3. 编辑一条消息，并 @ 某位群成员（例如消息末尾 @Henry）。
4. 发送该消息。
5. 观察已发送的消息气泡：@ 没有渲染出来，气泡内只剩纯文本，没有任何 @ 样式。
6. 返回会话列表，观察同一条消息的预览：@ 正常渲染（例如“2点在压测吗? @Henry”）。

## 预期结果
已发送的消息气泡应当正常渲染 @ 提及，带有 @ 样式和被 @ 成员的显示名，与会话列表预览以及 Web / 桌面端表现一致。

## 实际结果
消息气泡中 @ 未渲染，气泡只显示纯文本（无 @ 内容、无 @ 样式）。同一条消息在会话列表的预览中 @ 显示正常（“2点在压测吗? @Henry”），说明消息数据里 @ 是完整的，仅会话内气泡渲染层失效。

## 补充信息
- **功能区域**: 消息系统 / UI 渲染（@ 提及渲染）
- 反馈人：Jane（产品/质量）。反馈时间：2026-09-21。
- 关键证据：会话列表预览能正确渲染 @，而会话内消息气泡不能 —— 说明缺陷位于消息气泡渲染层，与 @ 解析、消息体、投递链路无关。
- 影响：@ 属于 IM 核心能力。用户无法看出消息中 @ 了谁，也无法确认 @ 是否发出，可能造成工作群内任务指派/通知被漏看。
- 回归范围：目前仅在移动端（iOS TestFlight 386）复现，Web / 桌面端渲染正常。
