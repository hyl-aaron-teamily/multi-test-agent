## Summary
On the Teamily iOS app, long-pressing a message whose content is only a link (a URL together with its link preview card, and no accompanying user text - a link-only message) produces no response at all: the message action menu never opens. Because the action menu is the only entry point for acting on a message, every operation on a link-only message becomes unreachable - most importantly quoting / replying to it, but also forwarding it, translating it, adding it to My Artifacts, deleting it and adding an emoji reaction. Text messages in the same conversation open the menu normally, so the failure is tied to the link message type rather than to long-press in general. Reported by Java (Teamily product team).

## Steps to reproduce
1. Open the Teamily iOS app and open a conversation that contains a link-only message (a message whose content is a URL plus its link preview card, with no accompanying text). In the reported case this is the conversation shown in the screenshot.
2. Long-press a plain TEXT message in the same conversation and confirm the action menu opens normally (emoji reaction row plus Reply, Ask AI, Translate, Copy, Forward, Multiple Selection, Add to My Artifacts, Report, Delete).
3. Now long-press the link-only message (press and hold on the URL / preview card).
4. Observe: nothing happens - no action menu, no reaction bar, no visual feedback. (This is the reported state; the screenshot shows the link-only message with no menu on screen.)
5. (inferred) Repeat in other conversations and with other link-only messages: the same no-response behaviour, while text messages keep working.

## Expected result
Long-pressing a link-only message should open the same message action menu that text messages get - including at minimum Quote/Reply, Forward, Copy (of the link), Add to My Artifacts, Delete and the emoji reaction row. A link message should not be a second-class citizen in the message action menu.

## Actual result
Long-pressing a link-only message produces no response at all - the action menu never opens. No action can therefore be performed on the message, so quoting / replying to a shared link is impossible. The screenshot shows the link-only message and confirms that no menu / action panel is on screen.

## Severity
- **Level**: High
- **Frequency**: Always

## Environment
- **Platform / OS / Browser**: iOS App (Teamily iOS)

## Additional context
- **Feature area**: Chat / Messaging - message action menu (long-press context menu)
- Message type affected: link-only message (URL plus link preview card, no accompanying text). Text messages in the same conversation are unaffected.
- Impact: the action menu is the only way to act on a message, so for a link-only message the entire operation surface is unreachable - quoting/replying, forwarding, translating, saving to My Artifacts, deleting and emoji reactions.
- Related: #2003 (iOS, open, P1) reports the same symptom but for IMAGE-only messages. That issue has been narrowed by engineering to a narrow selectable/hit area on image messages; a link message is a large card, so the hit-area explanation does not transfer. Recorded separately so that fixing #2003 does not silently leave link messages broken - full duplicate-check reasoning is in the triage comment.
- No workaround inside the app: there is no alternative entry point (no "more" affordance on the link card) reaching Quote/Reply.
- Screenshot: the affected link-only message is a Figma link sent by Ivy, rendered as green underlined URL text inside a bubble plus a link preview card (domain figma.com, title "onboarding feedback").

## 摘要
在 Teamily iOS 端，长按一条内容只有链接的消息（纯 link 消息 —— 只有 URL 和链接预览卡片、没有附带文字）完全没有反应：消息功能面板（长按菜单）无法唤出。由于功能面板是对消息执行操作的唯一入口，纯 link 消息上的所有操作都不可达 —— 最主要是无法引用 / 回复，同时也无法转发、翻译、加入 My Artifacts、删除，也无法添加 emoji 表情反应。同一会话里的文字消息可以正常唤出菜单，说明问题与「链接消息」这一消息类型相关，而不是长按手势普遍失效。反馈人：Java（Teamily 产品团队）。

## 复现步骤
1. 打开 Teamily iOS App，进入一个包含纯 link 消息的会话（消息内容只有 URL 和链接预览卡片、没有附带文字）。反馈中即截图所示会话。
2. 在同一会话里长按一条普通【文字】消息，确认菜单正常弹出（emoji 表情行 + Reply、Ask AI、Translate、Copy、Forward、Multiple Selection、Add to My Artifacts、Report、Delete）。
3. 再长按那条纯 link 消息（按住 URL / 预览卡片）。
4. 观察：没有任何反应 —— 不弹菜单、不弹表情条、无视觉反馈。（这是反馈所述状态；截图中该纯 link 消息下方没有任何菜单。）
5. （推断）在其他会话、其他纯 link 消息上重复：表现一致，文字消息仍正常。

## 预期结果
长按纯 link 消息时，应像文字消息一样唤出同一个消息功能面板，至少包含引用 / 回复、转发、复制链接、加入 My Artifacts、删除以及 emoji 表情行。链接消息不应成为消息菜单里的「二等公民」。

## 实际结果
长按纯 link 消息后完全没有反应，功能面板始终不出现，因此无法对该消息执行任何操作 —— 分享的链接无法被引用 / 回复。截图展示了该纯 link 消息，并确认屏幕上没有任何菜单 / 操作面板。

## 补充信息
- **功能区域**: 聊天 / 消息系统 — 消息功能面板（长按菜单）
- 受影响消息类型：纯 link 消息（URL + 链接预览卡片、无附带文字）。同一会话中的文字消息不受影响。
- 影响：功能面板是对消息执行操作的唯一入口，因此纯 link 消息的整个操作面都不可达 —— 引用/回复、转发、翻译、加入 My Artifacts、删除以及 emoji 表情反应。
- 关联：#2003（iOS，开启，P1）报告了同类症状，但对象是【纯图片】消息。该单已被工程收敛为「图片消息可长按选中的面积特别窄」；而链接消息是一张大卡片，触控热区的解释无法套用。此处单独建单，以免修完 #2003 后链接消息被静默遗留 —— 完整查重推理见分诊评论。
- App 内无变通方案：链接卡片上没有任何「更多」入口可以通往引用 / 回复。
- 截图：受影响的纯 link 消息是 Ivy 发送的 Figma 链接，渲染为气泡内绿色带下划线的 URL 文本 + 链接预览卡片（域名 figma.com，标题「onboarding 反馈」）。
