## Summary
On the Teamily Web client, typing "@" in the message input of a chat conversation intermittently fails to open the member/agent selection picker, so the user cannot mention anyone. Switching to another conversation and back restores the picker. Reproduced during a live meeting by the reporter. Suspected root cause: the @-mention member list is not reloaded / its state is not reset on conversation switch (stale cache, or a failed member-list request that is not retried).

## Steps to reproduce
1. Open a chat conversation in the Teamily Web client.
2. In the message input box, type "@" to start a mention.
3. Observe that the member/agent selection picker does not pop up (intermittent — happens sometimes, not every time).
4. Switch to another conversation, then switch back to the original one.
5. Type "@" again — the picker now appears and mentioning works normally.

## Expected result
Typing "@" in the message input box reliably opens the member/agent selection picker, allowing the user to mention any member or agent, regardless of how the conversation was entered.

## Actual result
The @-mention selection picker sometimes does not appear after typing "@" — no member/agent list is shown and the user cannot mention anyone. The feature only recovers after switching to another conversation and back. Confirmed on the Web client, also reproduced during a meeting.

## Severity
- **Level**: Medium
- **Frequency**: Intermittent

## Environment
- **Platform / OS / Browser**: Web

## Additional context
- **Feature area**: Messaging / @-mention
- Suspected cause: @-mention member list loading or state refresh issue — the picker state is not reset when the conversation changes, the member-list request fails silently, or a stale/corrupted cache is used.
- Suggested investigation: check the mention member-list request on conversation switch (does it re-fire? is the response cached?); verify the picker open-state / member-list state store is reset on conversation change; add a retry or re-fetch path when the member list is empty/stale.

## 摘要
在 Teamily Web 端会话中，输入 @ 时有时候不会弹出成员/Agent 选择框，导致无法 @ 人；切换到其他会话再切回来之后功能恢复正常。反馈人在一次会议中复现了该问题。疑似 @ 提及成员列表的加载或状态未刷新问题（如会话切换后选择框状态未重置、成员列表请求失败未重试、或使用了过期缓存）。

## 复现步骤
1. 打开 Teamily Web 端的一个会话。
2. 在消息输入框中输入 @，触发提及。
3. 观察成员/Agent 选择框没有弹出（偶现，并非每次必现）。
4. 切换到另一个会话，再切回原会话。
5. 再次输入 @，选择框正常弹出，可以正常 @ 人。

## 预期结果
在消息输入框中输入 @ 时应稳定弹出成员/Agent 选择框，用户可以 @ 任意成员或 Agent，且与进入会话的方式无关。

## 实际结果
输入 @ 后有时候不弹出成员/Agent 选择框，看不到任何成员列表，用户无法 @ 人；只有在切换到其他会话再切回来后才恢复正常。Web 端确认存在，会议中也可复现。

## 补充信息
- **功能区域**: 消息 / @ 提及
- 疑似原因：@ 提及成员列表的加载或状态刷新问题 —— 会话切换时选择框状态未重置、成员列表请求静默失败、或使用了过期/异常的缓存。
- 建议排查方向：检查会话切换时成员列表请求是否重新发起、响应是否被缓存；确认选择框开关状态与成员列表状态在会话变更时是否重置；成员列表为空或过期时增加重试/重新拉取逻辑。
