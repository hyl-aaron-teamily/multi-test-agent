## Summary
Improvement request raised by Aiden (P0, scheduled as a key iteration right after the China National Day holiday, i.e. from 2026-10-08). Today, when a user is @-mentioned in a muted (DND) group, the only cue is a small green '[@ mentioned]' text in the conversation-list preview. There is no new-message indicator, no unread badge on the conversation, and no count on the top-right / tab / app-icon badge, so users routinely miss messages addressed to them. Original feedback from Ellery Wang: 'When I am @-mentioned in a muted group there is only a green text hint, no new-message indicator or top-right badge, so I often miss group messages. Can we match WeChat, where any @ always produces a new-message indicator + badge?' Scope: (1) an @-mention addressed to me must always produce a new-message indicator + unread badge regardless of the group's mute state (WeChat parity); (2) add a Slack-style 'Mentions / @Me' aggregated list that collects every message that @-mentions me across all conversations in one place.

## Steps to reproduce
1. Mute (DND) a group chat on any client (Web / macOS / Windows / iOS / Android).
2. Have another member @-mention me in that muted group.
3. Observe the conversation list, the conversation's unread badge, the Chats tab / top-right badge and the app-icon badge.
4. Try to find all messages that @-mentioned me across groups — there is no single entry point for this.

## Expected result
(1) Any @-mention addressed to me (direct @me; @All/@Everyone per product rule) always shows a new-message indicator and increments the conversation's unread badge and the global (tab / top-right / app-icon) badge, even when the group is muted — matching WeChat. Muted groups' ordinary (non-@) messages keep the current silent behaviour. (2) A 'Mentions / @Me' list (Slack-style) aggregates every message that @-mentions me, newest first, with sender, group, time, message preview and read/unread state; tapping an item jumps to that message in context.

## Actual result
In a muted group an @-mention only renders a green '[@ mentioned]' text hint in the conversation preview. No new-message indicator, no conversation unread badge, no top-right / tab / app-icon badge count. There is no aggregated view of messages that mention me, so users miss them.

## 摘要
Aiden 提出的优化需求（P0，安排在十一假期后重点迭代，即 2026-10-08 起）。目前在 mute（免打扰）群里被 @ 时，只在会话列表预览里显示一个绿色的「[有人@我]」文字提示，没有新消息提示，会话没有未读角标，右上角 / Tab / App 图标也没有角标计数，用户经常错过 @ 自己的消息。原始反馈（Ellery Wang）：「新消息提示优化建议：现在在 mute 的群里被 @ 之后，只有一个绿字提示被 @，没有新消息提示或者右上角标，导致经常错过群消息，这种情况能否对标微信，只要被 @ 都有新消息提示 + 角标。」需求范围：(1) 被 @ 时无论群是否 mute，都要有新消息提示 + 角标（对标微信）；(2) 提供类似 Slack 的「@我的 / @Mention Me」聚合列表，集中查看所有 @ 到自己的消息。

## 复现步骤
1. 在任一客户端（Web / macOS / Windows / iOS / Android）将某个群设为免打扰（mute）。
2. 让群内其他成员在该群 @我。
3. 观察会话列表、该会话的未读角标、聊天 Tab / 右上角角标、App 图标角标。
4. 尝试集中查看所有群里 @我 的消息 —— 目前没有统一入口。

## 预期结果
(1) 只要有人 @我（直接 @我；@所有人 按产品规则），无论群是否 mute，都要有新消息提示，并计入该会话的未读角标和全局角标（Tab / 右上角 / App 图标），对标微信；mute 群的普通（非 @）消息保持现有静默行为。(2) 提供类似 Slack 的「@我的 / @Mention Me」列表，按时间倒序聚合所有 @我 的消息，展示发送人、所在群、时间、消息预览和已读/未读状态；点击可跳转到原消息上下文。

## 实际结果
mute 群里被 @ 时，仅在会话预览中显示绿色「[有人@我]」文字提示；没有新消息提示、没有会话未读角标、没有右上角 / Tab / App 图标角标计数；也没有 @我 的聚合入口，导致经常错过群消息。
